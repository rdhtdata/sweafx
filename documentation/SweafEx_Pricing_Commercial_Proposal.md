## 1. Executive Summary & Operational Pipeline

SweafEx operates an established freight brokerage business handling approximately 10 trips per day with a dedicated 10-person team. The proposed **SweafEx Digital Operations Platform** centralizes day-to-day freight execution into a single source of operational truth.

### The Connected Operational Flow
```text
CUSTOMER → ENQUIRY → QUOTE → ORDER → PLACEMENT → TRIP → TCN → POD → COMPLETION
                             ↕
          CONNECTED EXTERNAL INTERACTION LAYER
[ Customer Web Portal • Driver/Vendor Mobile Web • WhatsApp Business API ]
```

* **Enter Once → Reuse Throughout:** Eliminates re-typing vehicle numbers, copying rates between spreadsheets, manual phone chasing for basic milestones, and searching through WhatsApp chats for POD photos.
* **Higher Operational Capacity:** Creates additional operational capacity for the existing team by reducing repetitive administrative work as trip volume grows.
* **External Accounting Intact:** Zoho Books continues independently as SweafEx’s financial accounting system; the platform handles operational execution.

## 2. Phase 1 — What SweafEx Receives

Both commercial options include **100% identical Phase 1 functionality, scope, and deliverables**:

### Category 1: Internal Operations Platform
* **Role-Based Access:** Tailored workspaces for Sales, Traffic/Operations, Sales Backend, Accounts, and Management.
* **Customer Master & CRM:** GSTIN, corridors, payment terms, rate contracts, and active shipment feed.
* **Enquiry & Rate Board:** Customer rate vs transporter market costs side-by-side to protect gross margin before booking.
* **Transporter & Fleet Master:** Transporter agreements, vehicle RC/fitness/insurance compliance, and driver DL records.
* **Placement & EXP Generation:** 1-click vendor matching, margin calculation preview, and unique EXP trip generation.
* **Active Traffic Board:** Live operational tracking across standardized 13 milestone stages with exception alerts.
* **Automated TCN Workflow:** Instant pre-filled TCN PDF generation from existing trip data with 1-click dispatch.
* **5-Stage POD Lifecycle:** Pending → Soft Copy → Hard Copy in Transit → Hard Copy Verified → Submitted/Billed.
* **Accounts Commercial Review:** Pre-billing cost validation queue and clean data export for Zoho Books.
* **Universal Master Sheet:** Multi-filter global search across all active/completed trips with 1-click Excel export.
* **Management KPI Dashboard:** Live trip volume, margin health, pending placements, and overdue POD metrics.

### Category 2: Customer Web Portal
* **Zero-Install Web Portal:** Opens instantly via secure link on desktop or smartphone.
* **Live Shipment Tracking:** View active shipment progress (Confirmed → Loading → Transit → Delivered).
* **Document Self-Service:** 1-click download of verified TCNs and electronic POD copies.
* **Strict Data Isolation:** Clients only see information relevant to their organization.

### Category 3: Vendor & Driver Mobile Web Portal
* **Zero-Install Mobile Web Link:** Opens immediately from 1-click WhatsApp message (No Play Store / App Store download).
* **Field Driver Actions:** View dock addresses, 1-tap milestone buttons ("At Dock", "Loaded", "Delivered").
* **Camera Capture:** Direct photo upload of dock weighbridge slips and signed physical PODs.
* **Transporter Self-Service:** Confirm vehicle/driver assignments and accept agreed rates.

### Category 4: WhatsApp Business API Integration
* **Automated Operational Alerts:** Driver trip dispatch with 1-click tokenized update links.
* **Customer Notifications:** Booking confirmation and milestone delivery alerts.
* **Automated Document Dispatch:** Pre-filled TCN PDFs and POD availability notices.
* **Document Expiry Warnings:** Automated 30-day alerts for vehicle RC, fitness, insurance, and driver DL renewals.

## 8. Maintenance, Support & Service Coverage

> **Scope Principle:** The monthly maintenance fee covers the ongoing upkeep and support of the Phase 1 platform delivered as part of this project. It is intended to keep the existing functionality reliable and operational after launch. Maintenance applies strictly to EXISTING Phase 1 functionality.

### Core Maintenance Categories:

#### 1. Application Maintenance
* Bug identification and resolution within existing functionality.
* Resolving issues affecting agreed operational workflows.
* Application availability and health monitoring.
* Deployment of maintenance updates and dependency patches.
* Browser compatibility fixes for supported web and mobile browsers.
* Minor UI/UX text corrections required to maintain existing features.
* *Example: If an existing Trip Management workflow stops correctly displaying a trip status, this is a maintenance issue. Adding an entirely new Trip Management feature would be new development.*

#### 2. Technical Support
* Investigation of reported software issues and troubleshooting errors.
* Assistance with existing functionality and user/account access issues.
* Assistance with existing system configuration and deployment-related support.
* Guidance on using existing features and investigating failures within agreed Phase 1 integrations.
* *Support is intended for issues relating to the existing platform and agreed Phase 1 functionality.*

#### 3. Database, Backups & Platform Health
* Continuous database health and index monitoring.
* Routine database maintenance and automated backup monitoring.
* Verification of automated backup processes and storage utilization management.
* Investigation of database-related issues and recovery assistance where technically feasible.

#### 4. Security & Platform Updates
* Addressing known application-level vulnerabilities and deploying security patches.
* Core dependency/library maintenance and authentication/access-control upkeep.
* SSL/security configuration maintenance where applicable.
* *Note: Major security architecture changes or infrastructure migrations require separate estimation.*

### Integration & Portal Support Details:
* **WhatsApp Integration Support:** Covers agreed Phase 1 workflows (trip dispatch, customer alerts, portal links, TCN notices, POD reminders, approved templates). If an agreed workflow stops due to a software issue, investigation and fix are covered. Additional workflows, new message journeys or conversational bots are considered new development.
* **Customer & Vendor Portal Support:** Covers existing Customer Web Portal and Driver Mobile Web (bug fixes, token access, document upload/download, milestone updates, mobile browser compatibility). New portal modules are new development.

### Support Priority Guidance (Agreed Support Hours):
* **CRITICAL:** System-wide outage or issue halting core operations → Immediate investigation during support hours.
* **HIGH:** Major operational workflow impairment → High-priority investigation and resolution.
* **NORMAL:** Individual bugs, UI issues or non-critical defects → Scheduled into maintenance queue.
* **ENHANCEMENT:** Requests for functionality that does not exist → Treated as new development and separately quoted.

   * AI algorithmic matching or automated machine learning.
