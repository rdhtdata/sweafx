# SWEAFEX INTERNAL OPERATIONS MANAGEMENT SYSTEM

## DATA, PROCESS & FEATURE DOCUMENTATION

**Document Purpose:**  
To document the existing Excel sheets, CRM formats, WhatsApp communication formats and operational information currently used by SweafEx, and translate them into requirements for an internal operations management software.

**Source:** Existing SweafEx Excel formats, CRM examples, WhatsApp message formats and operational documents supplied by the company.

---

# 1. PURPOSE OF THE SOFTWARE

SweafEx currently manages its transportation operations using a combination of:

- WhatsApp messages
- Excel sheets
- Vendor databases
- Enquiry sheets
- Requirement sheets
- Placement sheets
- Trip confirmation sheets
- Trip status sheets
- Supplier/payment sheets
- Vendor and broker CRM sheets
- Rate cards
- Purchasing memos

The purpose of the new internal software is to replace this fragmented process with a **single centralized operational system**.

The software should allow SweafEx employees to manage the complete journey of a transportation requirement:

**Client Requirement → Enquiry → Vendor Search → Vendor Quotes → Vendor Selection → Vehicle/Driver Verification → Placement → Trip Confirmation → Trip Tracking → Delivery/POD → Supplier Payment → Trip Completion → Rating/CRM**

The system should maintain a single source of truth so that information entered once can automatically appear wherever it is required.

For example:

If an employee enters:

> Trip ID: EXP0369  
> Client: Micron Electricals India Pvt Ltd  
> From: Bangalore  
> To: Tuni  
> Vehicle: 20 Feet Open  
> Weight: 7 Tonnes

that information should automatically be available in:

- Requirement
- Placement
- Trip Confirmation
- Supplier Details
- Trip Status
- Purchasing Memo
- CRM
- WhatsApp confirmation

The user should not need to manually enter the same information into multiple Excel files.

# 20. REQUIREMENT VS ENQUIRY

The software should distinguish between:

### Enquiry

Initial transportation request.

Structured operational requirement that the team actively works on to find transportation.

Confirmed transportation assignment.

This separation is important because one enquiry may go through multiple stages before becoming a trip.

# 76. CRITICAL DESIGN PRINCIPLE

The final system should be designed around the **Trip lifecycle**, rather than around the existing Excel files.

The existing Excel files are representations of the process.

They should become:

```text

      ↓
BUSINESS LOGIC
      ↓
SCREENS / DASHBOARDS
      ↓
EXCEL EXPORTS
      ↓
WHATSAPP MESSAGES
      ↓
PURCHASING MEMOS
```

rather than:

```text
Excel Sheet 1
Excel Sheet 2
Excel Sheet 3
Excel Sheet 4
```

# 78. MOST IMPORTANT TAKEAWAY

The supplied SweafEx documentation shows that the company isn't really dealing with a collection of independent Excel sheets.

It is dealing with **one operational process that has been manually split across multiple spreadsheets and WhatsApp conversations**.

The software should therefore centralize these relationships:

```text
CLIENT
   ↓
ENQUIRY
   ↓
REQUIREMENT
   ↓
QUOTES
   ↓
VENDOR
   ↓
VEHICLE + DRIVER
   ↓
PLACEMENT
   ↓
TRIP
   ↓
TRIP STATUS
   ↓
POD
   ↓
PAYMENT
   ↓
RATING / CRM
```
